# Repository-Local Figure Reproduction Plan

## Purpose

This repository is the public data-availability and reproduction package for
the manuscript:

> First-principles analysis of in-plane anomalous Hall effect using
> symmetry-adapted Wannier Hamiltonians and multipole decomposition

The main goal is that readers who are interested in the paper can regenerate
the Python-plotted manuscript figures from this repository alone. The target is
scientifically equivalent figure reproduction: the same processed data,
curves, labels, and physical interpretation should be generated by repository
scripts. Byte-identical PDF output is not required, because plotting libraries,
fonts, and PDF metadata can differ across environments.

The repository should also contain the first-principles calculation inputs
needed to understand or rerun the DFT, Wannier, SymWannier, SAMB,
magnetization-rotation, and WannierBerri workflows. Large generated outputs,
especially HDF5 files and full work directories, should remain outside Git and
be documented by generation procedures.

## Repository Roles

Use the repository directories with the following meanings.

- `figures/paper/`: exact PDF files used in the manuscript. These are the
  reference figures copied from the paper workflow. They are kept for traceable
  comparison, not as proof that the current repository generated them.
- `results/figures/`: generated output from repository-local reproduction
  scripts. This directory is ignored by Git.
- `data/processed/`: compact CSV, XML, JSON, or metadata files consumed by
  plotting scripts.
- `scripts/reproduce_figures/`: Python scripts that read only committed
  processed data and write generated figures.
- `scripts/reproduce_all_figures.sh`: planned single entry point that runs all
  repository-local Python figure reproduction scripts.
- `inputs/`: planned location for committed DFT, Wannier90, SymWannier,
  MultiPie/SAMB, strain-cell, k-point, and WannierBerri input files.
- `scripts/workflow/`: extraction scripts and generation procedures for data
  products that require expensive or large intermediate files.
- `docs/`: human-readable mapping between manuscript results, data files,
  scripts, static assets, and large-file workflows.

## Figure Reproduction Categories

Every manuscript figure should be assigned one of these categories in the
figure inventory and documentation.

1. `reproducible_plot`
   - A Python-plotted figure that can be regenerated from committed repository
     data and repository scripts.
   - The generated plot should be scientifically equivalent to the manuscript
     figure, but exact PDF byte matching is not required.
   - Examples: AHC angular-dependence plots, rank-resolved AHC plots, strain
     plots, multipole coefficient bar plots, minimal-model plots, and
     band/bond convergence plots when compact data are available.

2. `static_asset`
   - A figure included as a static manuscript asset and not intended for
     repository-local regeneration.
   - Examples: Keynote-made schematics, QtDraw multipole drawings, crystal
     structure schematics, and definition diagrams.
   - These files may remain in `figures/paper/`, but documentation must clearly
     state that they are not regenerated by `scripts/reproduce_all_figures.sh`.

3. `workflow_required`
   - A result that requires expensive DFT, Wannier, SAMB, HDF5, rotated
     Hamiltonian, or WannierBerri generation before a compact plot can be made.
   - Files larger than 100 MB are not committed. The repository records the
     required inputs and generation procedure instead.

The current `reproducibility_level` language should be revised so that the
highest level means repository-local generation of an equivalent plotted
figure, not merely that the final manuscript PDF has been committed.

## Data And Input Policy

Commit files that are needed for reproducibility and are below 100 MB, unless
they are avoidable noise or private-machine artifacts.

Good candidates for Git:

- processed CSV, XML, JSON, or metadata files used directly by plotting
  scripts;
- small first-principles input files, including Quantum ESPRESSO `scf.in`,
  `nscf.in`, `pw2wan.in`, Wannier90 `*.win`, k-point scripts, strain-cell
  scripts, SymWannier settings, MultiPie/SAMB inputs, and WannierBerri input
  settings;
- compact summary outputs needed to avoid rerunning expensive calculations;
- README files that document units, source workflow, Fermi level, k meshes,
  strain values, rotation planes, and software versions.

Do not commit:

- HDF5 files or other generated outputs larger than 100 MB;
- full raw DFT, Wannier, or WannierBerri work directories;
- cluster logs, caches, scratch files, or generated binary intermediates;
- private absolute paths in executable scripts;
- cluster-specific submit scripts unless they are cleaned into portable
  examples or clearly marked as non-portable templates.

Pseudopotentials require a license check before redistribution. If a
pseudopotential cannot be committed, document its filename, source URL,
version, checksum, and expected destination path.

## Implementation Roadmap

### 1. Normalize The Figure Inventory

- Update `data/processed/figure_inventory.csv` so each manuscript figure has a
  category: `reproducible_plot`, `static_asset`, or `workflow_required`.
- For every `reproducible_plot`, record the exact processed-data file, plotting
  script, generated output filename, manuscript reference PDF, and figure
  group.
- For every `static_asset`, state why it is static, for example Keynote,
  QtDraw, or structure schematic.
- For every `workflow_required` item, link to the input files and generation
  procedure that would produce the missing compact data.
- Update `docs/paper_mapping.md` and `docs/data_inventory.md` to use the same
  categories and definitions.

### 2. Add One-Command Figure Reproduction

- Add `scripts/reproduce_all_figures.sh`.
- The script should create `results/figures/` and run all currently available
  Python plotting scripts.
- It should fail fast when a required processed-data file is missing.
- It should skip or report `static_asset` figures rather than pretending to
  regenerate them.
- It should print a short summary of generated files and missing follow-up
  items.

### 3. Complete Missing Processed Data

Extract or reconstruct compact data for the remaining Python-plotted figures:

- multipole coefficient CSV for `bar_ed_all_35.pdf` and
  `bar_ed_wo_q_35.pdf`;
- minimal-model CSV for `sigma_axis_model_1st_nn.pdf` and
  `sigma_axis_model_2nd_nn.pdf`;
- band/bond convergence data for `band_bond.pdf` if compact processed data are
  available below 100 MB.

Each processed-data directory should contain a README explaining:

- what each column means;
- the units;
- which manuscript figure group uses it;
- which source workflow produced it;
- whether any large intermediate files are required to regenerate it.

### 4. Commit First-Principles Inputs

Create `inputs/` and add the portable, under-100-MB inputs needed for readers
to understand or rerun the computational workflow.

Initial input groups should include:

- unstrained bcc Fe calculation inputs for the `(111)` and `(103)` rotation
  workflows;
- `[103]` strain inputs and strain-cell generation scripts;
- Wannier90 and `pw2wan` inputs;
- SymWannier/TRS-Wannier settings;
- MultiPie/SAMB generation inputs or metadata;
- WannierBerri AHC calculation settings;
- k-point and angle-grid generation scripts.

Each input group should have a README that states the calculation purpose,
required external software, expected command order, outputs that are kept out
of Git, and any pseudopotential requirements.

### 5. Document Large Generated Files

Keep HDF5 and other large outputs out of Git. For each large output class,
document:

- expected path;
- input files;
- command sequence;
- software versions;
- expected approximate size;
- checksum only when a local generated copy is available;
- downstream compact data extracted from it.

This documentation belongs in `scripts/workflow/generate_large_files.md` and
should be linked from `docs/data_inventory.md`.

## Testing And Acceptance Criteria

The default test suite should remain lightweight and should not require DFT,
MPI, WannierBerri, or HDF5 regeneration.

Required checks:

- `pytest` passes on fixture and processed-data tests.
- Every `reproducible_plot` inventory row points to an existing processed-data
  file and plotting script.
- `scripts/reproduce_all_figures.sh` can generate all available
  `reproducible_plot` outputs under `results/figures/`.
- Static assets are not marked as repository-generated plots.
- Processed-data tests cover compact numerical invariants such as row counts,
  angle grids, method labels, signs, and selected reference values.
- Input-file tests or inventory checks verify that planned input directories
  contain README files and expected manifests once `inputs/` is added.

Do not add default tests that require:

- rerunning DFT or WannierBerri;
- generating HDF5 files;
- accessing private production directories;
- comparing PDFs byte-for-byte;
- exact visual matching across plotting environments.
