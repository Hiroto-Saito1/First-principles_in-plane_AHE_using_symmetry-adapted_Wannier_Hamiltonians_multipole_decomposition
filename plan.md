# Reproducibility-First Repository Cleanup Plan

## Purpose

This repository is the public data-availability and reproduction package for
the manuscript:

> First-principles analysis of in-plane anomalous Hall effect using
> symmetry-adapted Wannier Hamiltonians and multipole decomposition

The repository should prioritize reproducibility over mirroring every visual
asset in the manuscript. A reader should be able to regenerate every included
numerical figure from files committed in this repository, or understand the
exact external first-principles/HPC workflow needed when the required
intermediate files are too large for Git.

The new rule is strict:

- every committed figure PDF must be generated by repository scripts or have
  explicit generated provenance;
- every committed CSV in `data/processed/` must have a reproducible upstream
  path from committed small source files or a documented full HPC workflow;
- static schematics, Keynote/QtDraw-style drawings, and manuscript composites
  that are not generated by repository scripts should not remain as tracked
  figure artifacts.

Byte-identical PDF reproduction is not required. Scientific reproduction is
the target: the same data, curves, labels, units, and physical interpretation
should be regenerated by repository-local commands.

## Repository Policy

### Figure Policy

`figures/paper/` should contain only reference PDFs for plots that can be
generated from repository data and scripts. The directory should not contain:

- static AHC-vector or rotation-plane schematics;
- crystal structure schematics;
- QtDraw-style multipole drawings;
- Keynote or manually assembled figures;
- `band_bond.pdf` until compact band/bond data and a plotting script are
  recovered.

Every manuscript figure remains listed in
`data/processed/figure_inventory.csv`, but it must use one of these categories:

- `reproducible_plot`: generated from committed repository data and a plotting
  script;
- `not_included`: static or manually composed manuscript asset not tracked as
  a repository figure artifact;
- `workflow_required`: numerical result that requires large generated
  first-principles/HPC outputs before compact plot data can be extracted.

The inventory must not use `static_asset` for included PDFs.

### Data Policy

`data/processed/` is not allowed to be an unexplained endpoint. Each CSV should
have:

- a committed small source file under `data/source/` when practical;
- one extraction or rebuild script under `scripts/workflow/`;
- README metadata naming the source file, command, output CSV, units, and any
  large-file dependency.

When a source CSV is recovered from manuscript vector PDF data, the README
must explicitly say that this is a fallback provenance path, not a regenerated
first-principles result.

### Large-File Policy

Files larger than 100 MB should not be committed. For each such file class,
document:

- expected path;
- required input files;
- command sequence;
- required software and version assumptions;
- expected downstream extraction command;
- checksum only when a generated local copy is available.

Pseudopotentials should remain uncommitted unless redistribution permission is
confirmed. Their filename, source, checksum, and expected destination path
should be documented.

## Reproduction Entry Points

The default reader-facing path should be lightweight:

```bash
./scripts/reproduce_from_inputs.sh
```

With no stage arguments, this should run only:

```text
extract -> figures
```

That means:

1. rebuild `data/processed/` CSV files from committed small source data;
2. generate all repository-backed figures under `results/figures/`.

The same driver should expose documented stages for the full workflow:

```text
dft
wannier
symwannier
multipie
rotate
ahc
extract
figures
```

The expensive stages should not run by default. If they are not fully
portable, they should print the exact recipe and input location rather than
pretending to launch a complete HPC workflow.

## Implementation Phases

### Phase 1: Clean Figure Policy

- Remove static, non-reproducible PDFs from `figures/paper/`.
- Reclassify static schematics as `not_included`.
- Reclassify `band_bond.pdf` as `workflow_required` until compact data and a
  plotting script are available.
- Update `figures/paper/README.md`, `docs/paper_mapping.md`, and
  `docs/data_inventory.md` so they no longer say that every manuscript PDF is
  committed.
- Replace tests that require every `main_all.tex` PDF to exist with tests that
  require every tracked figure PDF to be reproducible.

### Phase 2: Add Source Chains For Processed CSVs

- Create `data/source/`.
- Add committed small source snapshots for existing AHC, rank-resolved,
  strain, multipole, and minimal-model data where available.
- Add a rebuild script under `scripts/workflow/` that regenerates processed
  CSV files from committed source files.
- Document source file, command, output CSV, units, and upstream large-file
  dependency in each processed-data README.
- Keep PDF-vector recovery only as a labeled fallback for data whose original
  compact source was not preserved.

### Phase 3: Add The Reader-Facing Driver

- Add `scripts/reproduce_from_inputs.sh`.
- Keep the default path lightweight and workstation-safe.
- Add `--stage` support for `dft`, `wannier`, `symwannier`, `multipie`,
  `rotate`, `ahc`, `extract`, and `figures`.
- Route `extract` through the processed-data rebuild script.
- Route `figures` through `scripts/reproduce_all_figures.sh`.
- For incomplete HPC stages, print the recipe and required input files.

### Phase 4: Expand First-Principles Inputs

The public input tree should contain all redistributable under-100-MB files
needed to understand or rerun the calculation workflow:

- DFT inputs for unstrained bcc Fe;
- DFT inputs or cell-generation templates for `(111)`, `(103)`, and `[103]`
  strain workflows;
- Wannier90 and `pw2wannier90` inputs;
- SymWannier/TRS-Wannier settings and command wrappers;
- MultiPie/SAMB generation manifests or inputs;
- magnetization-rotation settings for `(111)`, `(103)`, rank-resolved, and
  strain workflows;
- WannierBerri AHC settings and job-generation wrappers.

Any manifest-only entry should be replaced with exact production input files
when those files are redistributable and under 100 MB.

### Phase 5: Recover Remaining Missing Figure Data

The highest-priority missing numerical item is `band_bond.pdf`.

To reintroduce it as a tracked figure:

1. recover or regenerate compact band/bond convergence data;
2. commit the compact source files under `data/source/`;
3. add processed CSV output under `data/processed/`;
4. add a plotting script under `scripts/reproduce_figures/`;
5. update the inventory category from `workflow_required` to
   `reproducible_plot`;
6. add lightweight tests for row counts, units, and expected numerical
   invariants.

The multipole-coefficient and minimal-model CSV files should also be replaced
with direct workflow outputs if the original compact data or clean
recalculation scripts are recovered.

## Tests And Acceptance Criteria

Default tests must remain lightweight. They must not require:

- Quantum ESPRESSO;
- Wannier90;
- SymWannier;
- MultiPie;
- WannierBerri;
- MPI;
- HDF5 generation;
- cluster access;
- private production directories;
- PDF byte-for-byte comparison.

Required default checks:

- every manuscript figure has exactly one inventory row;
- no inventory row uses `static_asset`;
- every tracked figure PDF appears in the inventory as a `reproducible_plot`;
- every `reproducible_plot` row points to an existing processed CSV and
  plotting script;
- every processed CSV has a committed source-chain path or labeled fallback
  provenance;
- `scripts/reproduce_all_figures.sh --check` verifies both processed and
  source files;
- `pytest` validates compact numerical invariants such as row counts, angle
  grids, method labels, signs, and representative reference values.

## Current Known Gaps

- `band_bond.pdf` still requires compact band/bond convergence data and a
  plotting script before it can be tracked again.
- Some source snapshots are compact production exports rather than raw
  first-principles outputs. This is acceptable as an immediate source chain,
  but the full HPC route must remain documented.
- Multipole-coefficient and minimal-model CSV files currently rely on
  PDF-vector recovery. This should be replaced by direct workflow outputs if
  the original source data or recalculation scripts are recovered.
- Some `inputs/` entries are manifests or cleaned templates rather than exact
  complete production command trees. They should be expanded as the original
  redistributable inputs are curated.

## Completion Definition

The cleanup is complete when:

- a reader can run one lightweight command to rebuild all committed processed
  CSV files and regenerate every repository-backed plot;
- every committed figure PDF is generated by repository scripts;
- every processed CSV has source provenance and a rebuild command;
- expensive first-principles stages have precise input files and documented
  commands;
- no file larger than 100 MB is committed;
- tests enforce the policy without requiring private directories or HPC
  software.
