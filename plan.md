# Full Reproduction Repository Plan

## Purpose

This repository is the public data-availability and reproduction package for
the manuscript:

> First-principles analysis of in-plane anomalous Hall effect using
> symmetry-adapted Wannier Hamiltonians and multipole decomposition

The goal is that a reader can fully reproduce the manuscript's calculations
and Python-plotted figures from files committed in this repository.
Lightweight distribution is not the priority. The single hard rule is that no
individual file larger than 100 MB is tracked in Git.

Concretely:

- every redistributable input under 100 MB used in the manuscript workflow
  (Quantum ESPRESSO `scf.in` / `nscf.in` / `projwfc.in`, Wannier90 `*.win`,
  `pw2wannier90` `*.in`, `submit.sh`, MultiPie input scripts, SymWannier
  command wrappers, WannierBerri settings, magnetization-rotation drivers)
  must be committed under `inputs/`;
- every committed figure PDF must be generated by a repository script, or be
  recorded as `not_included` because it is a static schematic;
- every committed CSV/JSON in `data/processed/` must have a documented
  upstream path: a committed compact source under `data/source/`, or a
  documented large-file regeneration recipe;
- expensive single artifacts above 100 MB (e.g. `Hamiltonian.h5`, full SCF
  saves, WannierBerri intermediate files) are not tracked, but the exact
  command sequence to regenerate them from committed inputs is documented.

Byte-identical PDF reproduction is not required. Scientific reproduction is
the target: same data, curves, labels, units, and physical interpretation.

## Repository Policy

### Figure Policy

`figures/paper/` contains reference PDFs only for plots generated by
repository scripts. Static schematics, QtDraw drawings, and structure panels
stay in the inventory but are not tracked PDFs. Categories:

- `reproducible_plot`: generated from committed processed data + script;
- `not_included`: static or manually composed asset;
- `workflow_required`: numerical figure whose compact data still requires
  large generated files; recipe lives in `scripts/workflow/`.

### Code Policy

`src/symwan_multipie/` is the canonical Python package and includes:

- `symwannier/` — Wannierization (SW and PD paths), originally in
  `symwan_proj/src/symwannier/`;
- `wannier_utils/` — full set of analysis modules (berry, band, dos,
  exchange, fourier, boltz, mag_sym, parallel, …), originally in
  `symwan_proj/src/wannier_utils/`;
- `multipole.py`, `multipole_decomposition.py`, `single_multipole_reader.py`,
  `mag_rotation.py`, `energy_diff.py` — existing AHC / multipole / rotation
  modules.

External heavyweight dependencies (modified Quantum ESPRESSO 7.4.1, MultiPie,
WannierBerri) are not vendored. Their version, source URL, and required diff
are recorded under `docs/qe_patch/` and `inputs/`.

### Input Policy

`inputs/` contains all redistributable under-100-MB calculation inputs needed
to reproduce the production workflow. The following must each be a complete
production input set, not a manifest:

- `inputs/dft/fe_bcc_unstrained/`: SCF, NSCF, `projwfc.in`, k-mesh notes,
  spin-quantization axis, SOC settings, `submit.sh`.
- `inputs/dft/fe_bcc_strain_103/`: tensile/compressive `[103]` cell
  generator, per-strain SCF/NSCF inputs.
- `inputs/wannier/fe_bcc_unstrained/`: `pwscf.win`, `pw2wan.in`, projection
  blocks, disentanglement window, k-grid, SOC-consistent settings.
- `inputs/symwannier/fe_bcc/`: SW/PD command wrappers, TRS-Wannier settings,
  rotation-plane definitions, rank-filter manifest.
- `inputs/multipie/fe_bcc/`: full `Fe.py`, `Fe_model.py`, `submit_samb.sh`,
  expected output filename map.
- `inputs/wannierberri/fe_bcc_rotation/`: per-angle job templates for
  `(111)`, `(103)`, rank-resolved, and `[103]` strain workflows, including
  Fermi level, k-mesh, and adaptive integration settings.

Pseudopotentials are not committed. Their source, version, checksum, and
expected destination path are documented in `inputs/dft/README.md`.

### Data Policy

`data/source/` contains committed under-100-MB source files used to rebuild
`data/processed/`:

- production export CSV/TXT (e.g. `z_coefficients.dat`,
  `Fe-ahc_iter-0020.dat`, `angle_dep_ahc.xml`, `energy_diff_35*.out`);
- PDF-vector recovery only as a labeled fallback for figures whose original
  source was not preserved.

`data/processed/` contains compact CSV/JSON files consumed by figure scripts.

### Large-File Policy

No file above 100 MB is tracked. For each large class, document:

- expected path; required inputs; command sequence; required software with
  version; expected size; checksum when a local copy exists.

The active list is `scripts/workflow/generate_large_files.md`.

## Reproduction Entry Points

```bash
./scripts/reproduce_from_inputs.sh                 # default: extract + figures
./scripts/reproduce_from_inputs.sh --stage dft     # documented HPC recipe
./scripts/reproduce_from_inputs.sh --stage wannier
./scripts/reproduce_from_inputs.sh --stage symwannier
./scripts/reproduce_from_inputs.sh --stage multipie
./scripts/reproduce_from_inputs.sh --stage rotate
./scripts/reproduce_from_inputs.sh --stage ahc
./scripts/reproduce_from_inputs.sh --stage extract
./scripts/reproduce_from_inputs.sh --stage figures
./scripts/reproduce_all_figures.sh                 # processed CSV -> figures
```

Expensive HPC stages do not run by default; they print the recipe and
required input location.

## Implementation Phases

### Phase A: Build the source inventory

Create `docs/source_inventory.md`. For every manuscript figure and table,
list:

- manuscript label (`fig:bcc_planes`, `fig:rank103_all`, …);
- local production directory (under the two reference workspaces);
- generating script (`bar_plot.py`, `fit_ahc.py`, `plot_rank_contrib.py`,
  `strain_analysis.py`, …) and its required input files;
- whether the underlying calculation directory is currently captured in
  `inputs/` and `data/source/`;
- planned destination in the public repository.

The same document also lists, per workflow stage (DFT / Wannier / SymWannier
/ MultiPie / WannierBerri / rotate / extract / figures), the local source
directory and the planned repository destination. This is the single source
of truth for the reorganization.

### Phase B: Expand `inputs/` to full production inputs

Based on Phase A:

- Replace each existing `inputs/.../README.md`-only manifest with the actual
  under-100-MB production input set.
- Add SOC-aware DFT inputs (with spin-orbit, magnetization axis, and
  appropriate pseudopotential reference) for `FM_sqa_{z,103,111}` cases.
- Add SymWannier/TRS-Wannier driver scripts and the SW/PD selection used in
  the manuscript.
- Add MultiPie `Fe.py`, `Fe_model.py`, and `submit_samb.sh` from the
  original `tests/Fe/num_iter_0/multipie/Fe_all_35/`.
- Add WannierBerri per-angle drivers for `(111)`, `(103)`, rank-resolved,
  and `[103]` strain.
- Add `inputs/dft/README.md` with pseudopotential references (no UPF
  redistribution).

### Phase C: Expand `src/symwan_multipie/`

- Import `symwan_proj/src/symwannier/` verbatim into
  `src/symwan_multipie/symwannier/`. Adjust imports.

## Tests And Acceptance Criteria

Default tests remain lightweight. Required default checks:

- every manuscript figure has exactly one row in
  `data/processed/figure_inventory.csv`;
- every `reproducible_plot` row points to an existing processed CSV and
  plotting script;
- every committed `inputs/` subdirectory has a README listing required
  software, expected outputs, and downstream large-file dependencies;
- every processed CSV has a documented source-chain path or a labeled
  fallback provenance;
- `scripts/reproduce_all_figures.sh --check` verifies both processed and
  source files;
- `pytest` validates compact numerical invariants (row counts, angle grids,
  method labels, signs, representative reference values).

Tests must not require Quantum ESPRESSO, Wannier90, SymWannier, MultiPie,
WannierBerri, MPI, HDF5 generation, cluster access, or the private
workspaces.

## Current Known Gaps

- The unstrained SOC-aware DFT/Wannier templates and the cleaned generic
  SymWannier/WannierBerri drivers are now committed, but the rank-resolved,
  strain-specific, and original per-plane workflow snapshots from
  `FM_sqa_{103,111}` still need to be transferred or summarized where they
  carry unique settings not captured by the generic public drivers.
- `band_bond.pdf` source data is not yet committed.
- Multipole-coefficient and minimal-model CSV currently use PDF-vector
  fallback.
- Pseudopotentials are intentionally not redistributed.

## Completion Definition

The reorganization is complete when:

- `docs/source_inventory.md` lists every manuscript figure / table with
  local source and repository destination;
- `inputs/` contains complete under-100-MB production inputs for the
  SOC + magnetization-rotation workflow used in the manuscript;
- `src/symwan_multipie/` contains the full SymWannier and wannier_utils
  modules and tests pass;
- a reader can run `./scripts/reproduce_from_inputs.sh` to rebuild all
  committed processed CSV files and regenerate every repository-backed plot;
- every repository-backed figure PDF is generated by a repository script;
- expensive single artifacts above 100 MB are not tracked, but have an
  exact regeneration recipe and required-input list.
